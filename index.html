01 · 통신업 A사

원가 산정 업무 표준화와
재산정 기능 구현

담당자별 엑셀 업무를 공통 프로세스로 옮기고, 기초 데이터 변경에 따른 재산정 흐름을 구현했습니다.

JavaSpring엠로 프레임워크 (Polymer 기반)Oracle
업무 기준 정리·현업 협의
PM·PL 지원
화면·DB·API 설계
PM·PL과 공동 수행
프론트엔드·백엔드 개발
직접 담당

기존 문제

담당자마다 엑셀 입력 양식, 산정 기준·계산식, 검토 절차가 달랐습니다. 자료 취합 시 양식과 데이터를 다시 정리해야 했고, 결과 비교나 계산 근거 확인을 위해 담당자에게 개별적으로 확인하는 작업이 필요했습니다.

직접 구현한 기능

  • 공통 양식에 따른 원가 정보 입력·수정
  • 품목·조건별 산식을 적용한 원가 자동 계산
  • 산정 내역·계산 근거 조회 및 결과 비교
  • 검토 요청, 승인·반려와 진행 상태 관리

핵심 과제: 기초 데이터가 바뀐 이후의 처리

자재 원가, 자재 목록, 작업 소요 품목을 마스터 데이터로 관리하고 이를 취합해 총원가를 계산했습니다. 산정 이후에도 기초 데이터가 바뀔 수 있어, 변경 영향과 업무 진행 상태를 함께 고려해야 했습니다.

  1. 01기초 데이터 변경

    자재 원가·목록·작업 소요 품목

  2. 02영향받는 품목 확인

    변경 내용을 반영할 대상 판단

  3. 03상태 확인·대상 표시

    현재 재산정이 가능한 품목 표시

  4. 04사용자 선택 재산정

    선택한 품목의 원가 다시 계산

개선 결과

자료 취합 시 엑셀 양식과 데이터를 재정리하는 작업을 줄였습니다. 시스템에서 산정 결과를 비교하고 계산 근거를 확인할 수 있게 해, 담당자에게 별도로 확인해야 했던 업무를 개선했습니다.

02 · 제조업 B사

인터페이스 호출 구조 개선을 통한
처리 시간 단축

건별 전송과 중복 호출을 줄이고, 시스템 간 데이터 전달 구조를 개선했습니다.

개선안 검토·설계
팀과 공동 수행
개선 기능 개발
직접 담당

기존 문제

한 시스템에서 수신한 데이터를 다른 시스템으로 전달하는 과정에서 건별 전송과 중복 호출이 누적됐습니다. 인터페이스 호출 횟수가 많아지면서 전체 처리 시간이 길어졌습니다.

개선 방법

  • 묶음 전송 — 건별로 전달하던 데이터를 모아 호출 횟수 감소
  • 중복 호출 통합 — 동일 데이터에 대한 반복 처리 제거
  • 전달 구조 개선 — 시스템 간 불필요한 호출 축소

개선 결과

데이터 전달에 필요한 인터페이스 호출 횟수를 줄이고, 수신 데이터를 다른 시스템에 반영하는 데 걸리는 시간을 단축했습니다.

여러 프로젝트에 걸친 연계 경험

내·외부 시스템 인터페이스 개발·운영 개선

ERP, 결재, 기업 신용정보 등 내·외부 시스템을 대상으로 데이터 송수신 인터페이스를 개발했습니다.

  1. 01규격 협의

    상대 시스템 담당자와 데이터 항목·연계 규격 협의

  2. 02개발·업무 반영

    송수신 기능, 데이터 형식·코드 변환, 수신 데이터의 업무 반영 로직 구현

  3. 03테스트·오류 수정

    연계 테스트와 오류 원인 분석·수정

운영·개발 담당자를 위한 재처리 기능

송수신 데이터와 성공·실패 여부, 오류 내용을 이력으로 저장했습니다. 운영 담당자와 개발자가 화면에서 이력을 조회하고 실패한 건을 재처리할 수 있도록 구현했습니다.

오류 유형에 따른 복구 방식

  • 통신 오류 — 자동 재시도로 일시적인 오류에 대응
  • 데이터 오류 — 데이터를 수정한 뒤 수동 재처리

연계 시스템별 중복 반영 방지

연계 대상의 규격과 처리 방식에 따라 고유번호·처리 상태를 확인하거나 기존 데이터를 갱신하도록 구현했습니다. 수신 시스템에서 중복 여부를 판단하는 경우에는 해당 규격에 맞춰 연계했습니다.

운영 개선 결과

화면에서 실패 건을 재처리할 수 있게 해 별도 수동 조치를 줄였으며, 자동 재시도를 통해 일시적인 통신 오류에 대한 반복 대응을 줄였습니다.
